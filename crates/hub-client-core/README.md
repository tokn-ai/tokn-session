# tokn-hub-client-core

Portable pairing and cryptography shared by native hosts, installed apps, and
browser clients.

```toml
[dependencies]
tokn-hub-client-core = "0.1.1"
```

The `address`, `pairing`, `protocol`, and `secure` modules provide machine
references, pairing messages, identities, and Noise encrypted records.
Native and `wasm32` builds share the same cryptographic implementation; WASM
bindings support the browser viewer.

For interpreted applet guests, use `default-features = false`. This disables
the browser bindings and JavaScript entropy imports. Initialize the device
identity with `NoiseIdentity::from_secret` using protected host-generated bytes;
use a fresh host-generated 32-byte seed for each `ClientPairing::start_with_entropy`
and `NoiseInitiator::new_with_entropy` call. The embedding host must provide a
cryptographically secure random source. Seeds must never be reused or persisted.

The `exchange` module owns request chunking, response headers, bounded bodies,
terminal ordering and response credit. `events::EventParser` handles bounded SSE
frames, including split UTF-8. Native and applet clients share these state
machines; only their IO, entropy, storage and scheduling adapters differ.

Networking and endpoint authorization are supplied by the caller. A successful
Noise handshake authenticates keys; access to a host still requires its pairing
or saved-device policy. Use `tokn-hub-remote` for the native network client.
